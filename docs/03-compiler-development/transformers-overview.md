# Transformer Passes Overview

Reflaxe.Elixir uses an ordered set of **AST transformation passes** to bridge the semantic gap between:

- Haxe’s typed AST (imperative / OOP‑friendly shapes) and
- idiomatic Elixir (functional / immutable / pattern‑matching‑first).

This file is the “read me first” for working on passes.

## Where Passes Live

- Pass registry (ordering, enablement, grouping):
  - `src/reflaxe/elixir/ast/transformers/registry/ElixirASTPassRegistry.hx`
- Transformer entrypoint (registry execution):
  - `src/reflaxe/elixir/ast/ElixirASTTransformer.hx`
- Typed module capability analysis and exact pass ownership:
  - `src/reflaxe/elixir/ast/PassApplicability.hx`
  - `src/reflaxe/elixir/ast/transformers/registry/PassScopeManifest.hx`

  - `docs/05-architecture/PASS_REGISTRY_INVENTORY.md`

- Lean pipeline + golden LiveView fixture guide:

## Design Rules (Hard Requirements)

1. **Shape‑based, not name‑based**
   - Do not key transforms on app/domain identifiers (e.g., “todo”, “cancel_edit”).
2. **No band‑aids**
   - Fix the root shape or analysis; do not “skip” or “cap” patterns to hide bugs.
3. **Keep it linear**
   - Prefer one walk + symbol tables/analyzers over repeated full‑tree scans.
4. **Printer stays dumb**
   - Semantic rewrites belong in builder/transformer, not the printer.
5. **Scope from typed facts**
   - Put exact stable pass IDs in `PassScopeManifest`; decide module eligibility from annotations, compiler metadata, or structured AST nodes in `PassApplicability`.
   - Never infer applicability from fragments of a pass name, generated module name, file path, or application name.
6. **Do not infer replay redundancy from names**
   - A later, distinctly named replay may consume shapes created after the first pass. Remove or merge one only with ordering, idempotence, snapshot, and scoped/all-pass parity evidence.

## Pass Authoring Checklist

- Add hxdoc to the transformer: WHAT / WHY / HOW / EXAMPLES.
- Keep the transformer under ~2,000 LOC (extract helpers if needed).
- Add/update snapshots when output semantics change.
- Run `npm run docs:passes`, `npm run guard:pass-inventory`, and `npm run test:pass-scope-parity` after registry ownership or ordering changes.
- Verify the todo‑app boots via QA sentinel (async + deadline).

## Debugging Pass Work

- `-D debug_pass_metrics` — emits when a pass changes the AST.
- `-D debug_ast_pipeline` / `-D debug_ast_transformer` — stage‑level tracing.
- `npm run profile:passes:baseline` — bounded per-module pass counts and reference timings.
- `npm run test:pass-scope-parity` — compiles representative modules with scoped and legacy all-pass execution and compares every generated byte.

`-D reflaxe_elixir_disable_pass_scopes` exists only inside that verification path. It is not an authoring profile, release mode, or alternate backend, and normal source checkouts and built packages both use scoped execution.
